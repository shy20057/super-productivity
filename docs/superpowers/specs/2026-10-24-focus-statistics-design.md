# 数据统计：按任务归属的专注记录

日期：2026-10-24。状态：用户已确认，进入实施。

独立 builder check：2026-10-24，仅审阅设计，结论为
“nothing important left”。未运行测试，未将此结论视为实现或同步验证通过。

## 1. 已确认的需求与目的

用户需要侧边栏新增“数据统计”，用于回顾全部任务上的专注投入。
统计单位是一轮已结束的专注，而不是任务被勾选完成。
用户选择方案 B：记录专注与任务的关联，用任务分配图解释时间去向。
用户随后要求扩大图表类型，增加时间轴及日、周、月、年、总览。

已确认：

- 全部任务都在统计范围，不要求学习标签。
- 手动结束和倒计时耗尽均作为一轮结束。
- 整轮有效专注时长归入结束日，不按跨日经过时间拆分。
- 按后续确认的需求，手动结束或到时结束均将结束时对应的任务标记完成；休息结束和取消不完成任务。

以下为设计者提出、随本设计一并获用户确认的默认方案：

- 五个视图共用一个页面框架，默认进入本周。
- 提供可选项目筛选；默认所有项目，不新增全局设置。
- 显示专注轮数、涉及任务数，不把专注结束称为完成任务。
- 使用既有 DateService 的逻辑日边界，默认就是午夜。
- 更早的记录保留为“历史未分类”，不虚构任务和起止时间。

## 3. Approaches

| 方案                            | 好处                                       | 成本与限制                                   |
| ------------------------------- | ------------------------------------------ | -------------------------------------------- |
| A：仅统计已有专注时长数组       | 历史可直接使用，数据结构改动少             | 没有任务分配，无法真实绘制专注时间轴         |
| B：在既有专注记录上增加任务关联 | 能回答时间花在哪个任务，并支持时间轴与下钻 | 要处理新旧记录、暂停、任务切换、旧客户端编辑 |

用户选择 B。实现保持在现有 metric/focus-mode 内，不另建数据库、
容器、后端接口或一套平行的计时系统。

## 4. 页面结构与视觉

侧边栏：数据统计，导航到独立、按需加载的 /statistics 路由。
头部：标题、日/周/月/年/总览切换、上/下一周期、回到当前周期、
日期选择、项目筛选和“统计口径”。
通过 URL 查询参数保存视图、日期及项目，刷新和后退可恢复上下文。

每页开篇四个摘要：

1. 专注时长：已结束轮次的有效时长之和。
2. 专注轮数：记录数量，不是任务完成数量。
3. 涉及任务：有效任务身份去重；未知历史不算一个虚构任务。
4. 日视图为最长一轮；其他视图为有专注记录的天数。

视觉延续项目风格；草图使用低饱和绿、蓝、赭色帮助区分数据。
正式版本颜色、间距、阴影与动效均使用现有 CSS 变量；
不针对单页改写 Angular Material 内部样式。
手机端切为单列，保留五个尺度入口及可操作日期控件。
大型热力图允许其图表局部滚动，不让整个页面横向滚动。

按用户后续的精简要求，各视图只保留核心图表，摘要与筛选继续共用。

### 日

- 保留当日专注时间轴与任务时长分配两张图，分别回答“何时专注”和“时间用于哪个任务”。
- 任务多轮时长合并，卡片左侧为环形饼图，右侧为完整任务列表，逐行显示任务名和“2h05min30s”；小屏改为上下排列，不再提供时长/轮数切换。
- 时间轴仍可查看单轮记录的真实起止时间与有效时长。

### 周

- 仅保留每日专注总时长柱图；具体时长直接列在图下，不按项目堆叠。
- 周起始日跟随已有日期/地区设置。

### 月

- 仅保留紧凑整月日历，无记录月份也保留日期网格。
- 每日使用24小时占比环图，任务按标识稳定分色，未记录时段显示灰色底环。
- 保留日期、实际时长和轮数；未来日期禁用，点击日期进入日视图并保留项目筛选。
- 提供任务颜色图例，超过24小时填满环图并显示实际时长。

### 年

- 仅保留每月专注总时长柱图与直观时长标签，移除年度热力图和结束时段矩阵。

### 总览

- 仅保留累计专注时长曲线；长历史继续按年/月聚合。
- 摘要显示累计实际时长，曲线提示与精确值使用小时/分钟格式。

移除重复的任务排行、项目分配、专注长度、星期分布、最近轮次卡片及独立数据明细卡片。
不添加切换开关来隐藏这些冗余图表，也不改变专注记录和统计口径。

## 5. 统一统计契约

### 完成、暂停与取消

- 使用现有 completeFocusSession 完成路径，含倒计时、番茄钟、
  自由专注的正常结束。
- 暂停不入账，继续后仍属同一轮；休息不入账。
- 取消/放弃不入账；点击结束专注属于手动完成。
- 普通任务的播放/暂停累计工时不自动产生专注轮次。
- 继续复用现有至少 1 秒的记录下限，不新增任意完成比例门槛。
- 正在计时的轮次不出现在统计汇总，用户结束后再显示。
- 完成事件仅生成一条专注记录，刷新、回放、重复事件不重复入账。

### 日期、时区与跨日

- 结束事件在服务边界通过 DateService 得到 day，
  reducer/selector 只使用载荷中的固定日期，回放时不重新读当前时间。
- 尊重已有跨日偏移，默认午夜；周起始、日期显示尊重现有本地化设置。
- 结束时的 day 一旦记录，设备后来更换时区不重新归属历史记录。
- 跨日的整轮时长归到结束日。
- 时间轴允许显示“前一天开始”标记，并保留真实起止时刻。
- 夏令时按日期加减处理，不用固定 24 小时推算自然日。

### 时长与任务切换

- 用已有计时的有效 elapsed/delta 作为统计来源，扣除暂停与休息，
  不用 endedAt - startedAt 替代它。
- 同一轮中切换任务，按各任务实际有效片段累计分配。
- 同一任务重复进入，只保留一项累计分配，不持久化逐秒采样。
- 无任务绑定的有效片段归为“未关联任务”；不能归给最后一个任务。
- 各任务分配时长加未关联时长必须等于该轮有效总时长。
- 一轮覆盖两个任务，轮数仍为一，涉及任务为二。
- 项目筛选后的轮数是“含该项目有效片段的不同轮数”，时长仅取该项目
  的分配部分。多个项目轮数不可相加为全局轮数。
- 任务分配图切换到轮数时，同轮涉及多个任务可在各任务各计一次；
  因为其合计不等于总轮数，图表应改为任务参与轮数条形图并明确说明，
  不画成一个暗示可加总的饼图。单任务草图的环图是简化演示。

### 缺失、空值与历史

- 已过去且无记录的日期显示零；未来日期显示未到来，不进入平均值分母。
- 默认平均值按有记录日计算并显式命名，避免暗示整月日均。
- 旧 focusSessions 只有时长：可用于时长、轮数、趋势、日期热力图、
  长度分布，任务归为历史未分类；不补造任务、起止或结束方式。
- 未知任务、未知项目、历史未分类分别命名，不混为一个虚构实体。
- 筛选已知项目时，未分类历史不进入结果，并提示筛选口径。
- 删除或归档任务不删除已记录的专注；使用结束时任务/项目名称快照，
  后续改名不会重写历史。删除后名称作为历史显示，不提供失效跳转。
- 图表无数据展示解释和“开始一轮专注”入口，不展示示例数据充当真实统计。
- 加载、读取失败、无数据是三个独立状态；读取失败提供重试。

## 6. 数据与兼容性约束

现状：Metric.focusSessions?: number[]，每天保存各轮 duration；
FocusModeEffects.logFocusSession$ 调用 MetricService.logFocusSession。
每日编辑对话框可直接修改该数组，必须纳入兼容方案。

设计要求：

- 复用 METRIC 日实体及既有 LogFocusSession 操作；
  为载荷和持久化模型增加可选的元数据，缺失时有运行时默认值。
- 不能把 number[] 直接改成对象数组，不能默认 bump CURRENT_SCHEMA_VERSION。
- 新记录需有稳定轮次 id、结束日期、有效时长、可用的起止时刻/模式/
  结束方式、任务分配与历史名称快照。
- 新增元数据为每轮一条，任务分配按任务 id 聚合。
  不增加秒级采样、不另外保存聚合图表副本；总体与已有轮次记录同阶增长。
  本地个人历史全部保留：每天 10 轮约每年 3650 条是容量规划估算，
  不是实测；实现需以长历史检视占用，不能通过偷偷删历史“解决”。
- 开始、暂停、继续、切任务产生的未完成草稿随现有本机专注恢复数据
  保存，不在计时过程中同步每个片段；正常结束时才写一个 METRIC 操作。
- 同一个持久化操作原子地写 duration 与其可选元数据。
  不通过两个 effect 写两条可能只成功其一的记录。
- 引用 task/project id 不意味着写 task/project，不声明多实体写入。
- 新客户端新增字段均为可选；旧客户端继续看到原 duration 数组。
- 元数据必须能够验证仍对应当前 duration 数组。设计者建议使用稳定
  轮次身份及源数组内容摘要。旧客户端重写数组导致摘要不匹配时，
  原时长数组仍是总计来源，关联详情降级未知，不能按旧下标误关联任务。
- 新客户端编辑某条时长、删除或补录记录时，同一操作内更新关联。
  人工补录无起止时刻时不绘制精确时间轴；更改时长使片段无法核对时
  降级为未分类，不能编造分配。保留其他未受影响记录的关联。
- 统计总时长不得同时累加 duration 数组和元数据，避免双计。
- 远程回放不启动计时、不产生第二条完成记录；LOCAL_ACTIONS 为 effect 来源。
- 同日不同设备记录的冲突必须使用既有单 METRIC 实体通路；
  不能新增长期冲突例外或绕过安全停止。计划阶段先核对现有通路的
  内容保留行为，再决定字段补丁的具体形状，不承诺未验证的并发无损。

## 7. 实现边界与维护成本

- 页面组件使用 standalone、OnPush、Signals/computed。
- 统计聚合为独立纯函数/小服务，日/周/月/年/总览共用。
- 复用 Chart.js 的惰性加载；时间轴、日历优先复用现有 UI 和轻量 SVG。
- 只渲染当前视图；不在任务行上增加订阅、计算或模板函数调用。
- 聚合缓存按数据修订及日期范围失效；每秒计时不重建长期图表。
- 数据明细分页；项目数量多时保留 Top N + 其他并可查看完整表。
- 不加根依赖，不需 PostgreSQL、容器或服务端变更。
- 不新增公共/plugin API。持久化模型的新增可选字段是主要维护风险。
- 更新用户文档；翻译依仓库约定由 en.json 和 T 管理。
  中文菜单“数据统计”的实现需要遵守本仓库翻译约束；不擅自修改
  用户现有未跟踪 src/assets/i18n/zh-wip.json。
- 不改 AGENTS.md、CLAUDE.md、.agents 或 .codex。

## 8. 可访问性

- 图表有标题、单位、图例、文字摘要和可读取的精确数据表。
- 数据不能仅用颜色表达；状态/项目有文字标注，热力图有数值说明。
- 交互图形支持键盘，日期和筛选有标签，焦点可见。
- 弹窗支持焦点管理、Escape 与返回触发点，复用现有共享弹窗。
- 尊重 reduced-motion；手机端控件保持足够触摸面积。

## 9. 验收与验证安排

以下是待实现的验收条件，不表示已经执行：

1. 手动结束、倒计时结束各入账一次；暂停/取消/休息不入账。
2. 跨午夜、跨月、跨年、跨时区回看及非午夜逻辑日归属正确。
3. 同轮切换任务、同任务多轮、无任务片段均守恒。
4. 日视图之和等于周/月/年/总览对应范围之和。
5. 旧数据、旧客户端改数组、补录、编辑、删除均不造成错配或双计。
6. 回放、重启恢复、不同设备并发与归档后查看不制造重复记录。
7. 浅色/深色、手机、长任务名、大数据及空状态可读。

用户明确要求：不主动运行测试；认为需要测试时先请求其批准。
开发时编写新增状态/聚合服务所需的测试，但获批前不运行。
修改的 .ts/.scss 按仓库要求执行 checkFile 格式与 lint；如果用户把
这些静态检查也包含在“测试”限制内，先澄清再执行。
构建/渲染与测试结论分开报告；没有获批和运行的测试不得声称通过。

## 10. 草图与交付顺序

交互草图位于本次可视化工作目录，带明显“示例数据”标记。
包含五个时间尺度、日期与项目切换、图表下钻、详情、数据表、深浅色。
草图不接入真实任务、不写应用状态，是设计讨论用的可丢弃原型。

先确认五页设计与本契约，再按 writing-plans 形成实现计划。
实现顺序：记录与兼容 → 共用聚合 → 五个视图 → 导航/翻译/文档 →
获批的验证。不能交付仅有演示数据的页面冒充功能完成。

留给实现者：可复用组件的细粒度拆分、具体 SVG 尺寸、图表轴刻度、
元数据字段的具体命名、源摘要算法及聚合缓存形式。
若真实同步路径无法满足兼容约束，应先缩小数据设计，不增加新同步协议。
